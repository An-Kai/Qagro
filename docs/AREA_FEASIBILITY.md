# Посевные площади как фича против сдвига масличных — feasibility-отчет

- Дата: 2026-09-20. Роль: data-исследователь Qagro.
- Ограничение: панель/модели не трогал, только чтение + этот файл. `data/raw/sown_area.csv` **не создавал** (чтобы не плодить второй новый файл); ниже — готовая спецификация + скрипт-генератор + превью данных.
- Вопрос: объясняет ли рост урожайности рапса 13→19 ц/га в 2024 расширение площадей / структурный сдвиг в масличных, и можно ли добавить площади фичой вместо голого `year_trend`.

## 1. `data/raw/stat_yield.csv` — площадей НЕТ, только урожайность

- Путь: `Qagro/data/raw/stat_yield.csv`. Колонки: `year,district,crop,yield_c_ha,source`. Колонки площади (`area_ha`, `sown_ha`) отсутствуют.
- Размер: 1260 строк = 21 год (2005–2025) × 10 районов × 6 культур (`spring_wheat, barley, oats, sunflower, rapeseed, flax`).
- Источники в колонке `source` — якоря BNS/stat.gov.kz + APK-Inform/BNS 2022–2024 (рапс 2024 = 19.2, 2025 = 19.5), FAOSTAT QCL shape 2005–2021; районы = даунскейлинг `oblast_anchor × agrocoef`.
- Вывод: текущий файл не позволяет отделить «стало больше сеять» от «стало выше урожайность». Для проверки структурного сдвига нужен внешний ряд площадей.

## 2. stat.gov.kz, динамические ряды Акмолинской обл. — УСПЕХ (автоматом, без ключа/капчи)

- Страница: https://stat.gov.kz/ru/region/akmola/dynamic-tables/1485/ → раздел «Уточненная посевная площадь основных с/х культур».
- Прямые ссылки на файлы (GET 200, `application/vnd.ms-excel`, старый `.xls` OLE, 42–55 КБ, скачано и распарсено 2026-09-20, Python+xlrd):
  - Вся посевная: https://stat.gov.kz/api/iblock/element/region/40087/file/ru/ (25 строк: область + районы)
  - Зерновые (включая рис) и бобовые: https://stat.gov.kz/api/iblock/element/region/40088/file/ru/ (агрегат + блок «из них: пшеница» с 1991)
  - Масличные: https://stat.gov.kz/api/iblock/element/region/40090/file/ru/ (агрегат + подблок «подсолнечник»)
  - Картофель: https://stat.gov.kz/api/iblock/element/region/40089/file/ru/
  - Овощи открытого грунта: https://stat.gov.kz/api/iblock/element/region/40091/file/ru/
- Покрытие: **1991–2025, Акмолинская область + разбивка по районам** (~19 районов/г.а., включая Зерендинский). Единицы смешанные — **1991–1998 в тыс. га, 1999–2025 в гектарах** (вторая шапка «тыс.га … в гектарах»); при сборке умножать 1991–1998 на 1000.
- Детализация культур (важно для вопроса про рапс): **только агрегаты** — зерновые всего (+ пшеница отдельно), масличные всего (+ подсолнечник отдельно). **Рапса и льна отдельно НЕТ** ни в областных рядах, ни в районных. Подсолнечник — единственный масличный с разбивкой.

## 3. data.gov.kz / egov API — за таймбоком не взято (остановлено по условию)

- API v4 для разработчиков существует (`/api/v4/dataset?source={...}`, доки https://data.egov.kz/pages/samples), но готового датасета «посевные площади по районам Акмолинской обл., 2005–2025, рапс/подсолнечник» в выдаче за быстрый поиск нет; портал требует подбор dataset-id/version вручную.
- Open-data БНС по сельскому хозяйству (https://stat.gov.kz/open-data/agriculture-and-land-use/ и /ru/...): есть «18.1 Убранная площадь отдельных с/х культур», но это **убранная**, не посевная, и без районно-культурного разреза 2005–2025 за 2 клика. Ручной перебор xlsx не делал (стоп по условию задачи).
- Вердикт: data.gov.kz — «недоступно автоматом за 10 минут», оставить как бэклог (поиск dataset-id + маппинг полей), приоритет ниже, т.к. stat.gov.kz уже дает то же покрытие.

## 4. FAOSTAT area harvested (Казахстан) — НЕДОСТУПЕН из этой сети (2+ запроса)

2. `GET https://fenixservices.fao.org/faostat/api/v1/QCL/AreaCodes/E231?lang=en` (Python urllib, 25 с) → `TimeoutError: read timed out`.
3. Тот же `DomainCodes` через WebFetch → `521` (Cloudflare: хост недоступен). Контрольная страница https://www.fao.org/faostat/en/#data/QCL отдала только JS-оболочку без данных.
- Вердикт: открытый API `fenixservices.fao.org/faostat/api/v1/...` из текущей сети недоступен; bulk-ZIP (`bulks-faostat.fao.org/production/...`) в таймбоку не тянул (тяжелый, плюс те же риски сети). FAOSTAT держать как валидацию формы 2005–2021 (как уже сделано в `stat_yield.csv`), а не как источник площадей 2005–2025 по области/районам — его там и нет в нужном разрезе (только страна).

## 5. Готовый CSV: спецификация + генератор (файл не создан — см. шапку)

Формат `data/raw/sown_area.csv`: `year,crop,area_ha,source`, где `crop ∈ {total, cereals, oilseeds, sunflower}` (область) или district-ряд с колонкой `district` при районной сборке; `area_ha` — гектары (1991–1998 ×1000 при конвертации); `source` — `BNS stat.gov.kz dynamic-tables akmola/1485 fileId=40087/40088/40090 (+row label), unit-normalized`.

Превью (область, га):

Генератор (одна команда, без ручного xlsx; зависимости `xlrd`; воспроизводит обл.+районные ряды 1991–2025 с нормализацией единиц):

```python

# xlrd-парсинг: years=row3, oblast=row4/5, districts=rows 5..N; 1991-1998 *1000 -> ha;

# запись data/raw/sown_area.csv: year,[district],crop,area_ha,source
```

Проверенные числа для сверки генератора: см. таблицу раздела 2 и район-Зеренда; сумма районов ≈ итогу области (проверять assert <1%).
