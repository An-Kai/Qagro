# GIS-мониторинг полей — Трек 1 (простыми словами)

Это проверка полей со спутника. Берём границы полей и смотрим,
как они зеленели летом 2024. Зелень меряем индексом **NDVI**:
ближе к 1 — густые растения, около 0.2 — голая земля.

## Что на входе

- **Поля:** `data/fields/akmola_osm_fields.geojson` — 115 штук.
  Настоящие границы — из OpenStreetMap (лицензия ODbL),
  запасной источник — дамп Geofabrik Kazakhstan.
  Часть записей с `demo:true` — это честные прямоугольники-заглушки
  (где Overpass ничего не вернул), они НЕ выдаются за OSM.
- **Сцены Sentinel-2:** `data/ndvi/ndvi_timeseries.json` — список сцен
  (поиск через Microsoft Planetary Computer STAC, облачность < 20%).
  Новые сцены НЕ ищем: `scene_id` переиспользуем из этого файла.

## Как считается NDVI

1. Для поля берём его прямоугольник (bbox) и сжимаем до **0.02 градуса**
   (примерно 1.4 × 2.2 км) — так запрос идёт ~1 секунду.
2. На каждую дату (`2024-06-03, 2024-06-13, 2024-06-18, 2024-07-12,
   2024-08-12`) берём **1–2 сцены с ТОЧНОЙ датой** того же района.
   Нет сцены — пишем `ndvi_mean: null` с причиной, число НЕ выдумываем.
3. Запрос уходит на сервер **PC TiTiler**:
   `POST .../api/data/v1/item/statistics`,
   `collection=sentinel-2-l2a`, `assets=B04,B08`,
   `expression=(B08-B04)/(B08+B04)`, `asset_as_band=true`,
   в теле — прямоугольник поля (GeoJSON).
   Сервер сам считает NDVI по пикселям каналов B04 (красный)
   и B08 (ближний инфракрасный) и отдаёт среднее — это и есть `ndvi_mean`.
4. Лимиты: **не более 6 полей за запуск**, таймаут **25 с**,
   ошибка сети — `null` с текстом причины.

## Как понимаем результат (пороги — эвристики, НЕ ГОСТ)

Считаем по датам с данными: `ndvi_max`, `ndvi_min`,
`amplitude = max − min`, `dead_share` — доля дат с NDVI < 0.3.

| Статус | Правило | Что значит для агронома |
|---|---|---|
| `likely_fallow` | amplitude < 0.15 | Возможно, поле не обрабатывается: зелень ровная и низкая весь сезон |
| `sparse` | max < 0.35 (а ход не ровный) | Изреженные всходы / возможна гибель |
| `cultivated` | иначе | Поле обрабатывается, зелёная масса есть |
| `no_data` | нет ни одного NDVI | Спутник не дал данных (облака/сеть) |

Пороги подписаны как **эвристики из агро-практики, не ГОСТ**:
граница 0.15/0.35/0.3 подобрана под яровые Акмолы летом,
для других культур и регионов её надо перепроверять в поле.

## Файлы выхода

- `data/gis/gis_{район}.json` — по каждому полю: серия NDVI по датам
  (`{date, ndvi_mean|null, scene_id, note}`) + классификация.
- `data/gis/gis_summary.json` — итоги:
  `{total_fields, checked, cultivated, sparse, likely_fallow, avg_ndvi_max}`.

Запуск:

```powershell
python src/gis_monitor.py --district Esil --max 4
python tests/test_gis.py
```

## Как открыть в QGIS

1. QGIS → Слой → Добавить слой → Добавить векторный слой.
2. Источник — файл `data/fields/akmola_osm_fields.geojson`
   (открывается напрямую, это обычный GeoJSON, WGS84).
3. Стиль: раскрасить по полю `demo` (настоящие OSM / заглушки)
   или присоединить `data/gis/gis_Esil.json` по `field_id` для карты статусов.
4. Подложка: Модуль QuickMapServices → OSM / Google Satellite —
   визуально сверить границы.

## Ручная проверка (обязательные ресурсы хакатона)

| Ресурс | Ссылка | Как использовать |
|---|---|---|
| Sentinel-2 — Copernicus Browser | https://browser.dataspace.copernicus.eu/ | Найти сцену по дате и координатам, посмотреть RGB и NDVI |
| Sentinel-2 — Sentinel Hub | https://www.sentinel-hub.com/ | EO Browser: тот же снимок, готовый слой NDVI |
| Sentinel-2 — PC STAC API | https://planetarycomputer.microsoft.com/api/stac/v1 | Источник списка сцен (`sentinel-2-l2a`, без ключа) |
| Landsat 8/9 — EarthExplorer | https://earthexplorer.usgs.gov/ | Перекрёстная проверка: сцена Landsat на ту же дату |
| Landsat 8/9 — LandsatLook | https://landsatlook.usgs.gov/ | Быстрый просмотр Landsat без скачивания |
| OSM / Geofabrik (ODbL) | https://www.openstreetmap.org/copyright, https://download.geofabrik.de/asia/kazakhstan.html | Лицензия границ полей; офлайн-дамп Казахстана |
| QGIS | https://qgis.org/ | Открыть GeoJSON, сверить поле с подложкой |
| EarthMap | https://www.earthmap.org/ | Независимая проверка NDVI/погоды по точке поля |

Если наш NDVI спорит с картинкой в Copernicus Browser / LandsatLook /
EarthMap — верим картинке и едем в поле: спутник не заменяет осмотр.

## Ограничения (честно)

- **Bbox вместо маски поля.** Считаем прямоугольник, а не точные пиксели
  внутри границы. Края могут цеплять дорогу/лесополосу. Точная маска —
  следующий шаг (нужен rasterio и чтение COG).
- **Сцены только из готового списка.** Даты без сцены (`2024-07-12` для Esil)
  дают `null` — дырка в ряде, а не ноль.
- **Облака.** Сцены отобраны с cloud < 20%, но лёгкая дымка внутри bbox возможна.
- **Демо-поля.** У Esil все 3 поля — `demo:true` (прямоугольники 1×2 км),
  это НЕ настоящие границы OSM, результат по ним — ориентир методики.
- **Пороги не универсальны.** 0.15/0.35/0.3 — эвристики, не ГОСТ.
